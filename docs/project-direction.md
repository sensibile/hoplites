# 프로젝트 방향과 개발 기준

2026-10-03 사용자와 합의한 방향입니다.

## 최종 목표

Hoplites의 최종 목표는 보안 증거와 라이선스 의무 이행을 근거로 배포를 관리하는 시스템입니다. 대상 환경은 Dev, Prod, 고객 On-Prem 등을 구분합니다. Slack의 배포 요청과 진행 공유에 흩어진 정보를 정확한 릴리스, 대상, 승인 근거와 실행 결과로 연결합니다. 침묵을 명시적 승인으로 간주하지 않는 방향을 지향합니다. 현재 회사의 별도 CI 통제나 실제 승인 규칙은 조사하지 않았으므로 기존 통제가 없다고 단정하지 않습니다.

아티팩트 digest → 원본·보강 SBOM → 보안 및 라이선스 평가 → 의무 이행 증거 → 배포 판단 → 실행 결과로 이어지는 추적을 목표로 합니다. 검사 통과, 사람의 승인, 실제 배포 성공은 별도 상태입니다.

## 현재 범위와 확장 경계

현재 목표는 아티팩트와 SBOM 연결 및 여러 이미지에서의 생성 품질 비교입니다. Syft를 기준으로 정규화 방향을 검증하고 Dependency-Track으로 분석 결과를 연결합니다. 오늘은 라이선스 전처리 구현이나 이행 관리까지 확장하지 않습니다.

후속 단계는 근거 있는 SBOM 보강, 라이선스 의무와 이행 증거 연결, 릴리스별 승인 및 배포 이력입니다. 각 단계의 작은 실험과 완료 기준이 확인된 뒤 확장합니다. 기존 레지스트리 및 아티팩트 저장소를 활용하는 방향이며 별도 레지스트리 개발은 현재 범위 밖입니다.

ReARM은 제품·구성요소·릴리스 모델, 원본 증거 보관, 발견 항목 검토 이력, VEX 및 Dependency-Track 연동의 기능 참고 대상입니다. 해당 프로젝트 전체를 도입하거나 같은 구조를 그대로 구현하기로 결정한 것은 아닙니다. 공식 설명: https://github.com/relizaio/rearm

## 언어 선택 기준

| 작업 성격 | 언어 |
| --- | --- |
| 기능 확장을 위한 웹앱과 서버 기능 | Elixir |
| 복잡한 로직이 필요한 CLI | Rust |
| 스크립트로 충분한 작업과 실험 자동화 | Python |

작업의 성격과 복잡성으로 선택합니다. 처음부터 세 언어의 서비스를 모두 만들거나 스크립트를 즉시 Rust로 옮기지 않습니다. CLI 복잡성이 스크립트 범위를 넘어설 때 전환 범위와 근거를 정합니다. 웹 프레임워크, CLI 인터페이스, 패키징, CI는 아직 결정하지 않았습니다.

## SBOM 처리 원칙

원본 SBOM을 보존하고 정규화·보강본은 별도로 생성합니다. 아티팩트 플랫폼 digest, 원본과 보강본의 SHA-256, 도구 버전 및 옵션, 변환 규칙 버전을 연결합니다.

패키지·애플리케이션·OS와 파일 증거를 구분합니다. 파일은 제거하지 않고 소유 패키지와 근거 있는 연결을 시도합니다. 파일명만 보고 라이선스를 추정하지 않습니다. 추가 정보에는 출처와 확인 상태를 남기고 확인하지 못한 정보는 unknown으로 유지합니다. Group은 생태계에 따라 없을 수 있으므로 일괄 생성하지 않습니다.

형식 정규화, 식별 및 라이선스 정보 보강, 의무 이행 관리는 서로 다른 단계입니다. 라이선스 빈칸은 라이선스가 없다는 뜻이 아닙니다. 라이선스가 발견됐다는 사실도 의무 이행 완료의 증거가 아닙니다.

BusyBox 같은 구성요소를 납품할 때는 적용 라이선스와 배포 방식에 맞는 고지, 대응 소스, 제공 방식 등을 검토하고 해당 릴리스의 증거에 연결합니다. 이행 상태는 완료·미완료·확인 필요를 구분하는 방향입니다. 의무를 법률 판단 없이 일괄 자동 확정하지 않습니다. BusyBox 공식 안내: https://busybox.net/license.html

## 실행 상태와 분석 상태

업로드 접수, BOM 처리, 취약점 분석과 데이터 갱신을 구분합니다. 이번 서버는 COMPLETED와 metrics 0개를 반환했지만 이는 취약점 데이터 동기화 완료나 안전성의 증거가 아닙니다. 사용자가 이후 화면 변화 가능성을 언급했으나 실제 취약점 발생을 재확인하지 않았습니다. 현재 결과와 과거 관측 시점을 혼동하지 않습니다.

## 현재 이미지 실행 경로

이미지 주소 입력부터 digest 고정, Syft/rootfs 수집, 적용 가능한 패키지·런타임 보강, 원본/정규화/증적 출력, 옵션 DT 업로드·Ubuntu VEX까지 연결했다. [이미지 파이프라인](image-pipeline.md)의 사용법과 규칙 추가 절차를 따른다. 각 실행의 미해결은 계속 관리하고, 실행 완료를 안전성 또는 라이선스 의무 이행 완료로 취급하지 않는다. 과거 첫 실험의 관측은 현재 서버 상태로 사용하지 않는다.
