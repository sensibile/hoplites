# ADR-0012: SAST 엔진 다중화와 에이전트 보완 루프의 측정 방식

상태: 채택(실험). 2026-10-30.

## 배경

2026-10-30 BOSS와 SAST 방향 C 단계("엔진 결과를 LLM 에이전트가 트리아지·보완하는 계층")를 합의했다. 무료 룰셋의 구멍을 메우는 방안으로 네 가지를 하나의 루프로 묶기로 했다: 언어·CWE별 정답 세트로 구멍 지도 만들기, 무료 엔진 다중화와 교차검증, 에이전트가 합성한 룰의 gate 통과 후 편입, 에이전트 탐색 가설의 PoC 확인. 저장소 `sensibile/hoplites`는 공개 저장소이고, 공개 벤치마크는 LLM 학습 데이터 오염 가능성이 있다. 미병합 브랜치 `feat/opengrep-cwe`가 JavaScript 대상 opengrep 파일럿을 남겼다.

## 결정

- 첫 실험은 Python Flask, CWE-89·78·22·918·502다. 엔진은 Bandit 1.9.4, opengrep 1.32.0(opengrep-rules `f1d2b56` 비교 기준), Joern v4.0.656이다. Semgrep CE는 opengrep과 같은 코드에서 갈라져 독립 교차검증이 되지 않으므로 넣지 않는다.
- Joern은 Python 기본 쿼리가 사실상 없어, 첫 스캔 전에 사전 등록한 source·sink 모델 v0를 기준선으로 쓴다.
- 정답 세트는 공개 저장소 밖 로컬 저장소에 둔다. 저장소에는 하네스, 룰, 집계값, 해시만 커밋한다. sink는 줄 번호가 아니라 함수+호출 이름으로 지정해 코드에 표식을 남기지 않는다. 사례마다 PoC로 취약·수정 상태를 검증한다.
- 개발용(dev)과 독립(holdout) 세트를 나눈다. 룰은 dev confirmed 사례로만 합성하고 커밋으로 동결한 뒤 holdout을 잰다. holdout 작성자는 격리된 별도 에이전트다.
- 측정은 수집(`sast_engines.py`, `sast_normalize.py`, `sast_agent.py`), 계산(`sast_measure.py`), 판정(`sast_rule_gate.py`)으로 나눈다. 매칭은 sink 위치 겹침과 사전 정의한 CWE 허용 집합(strict)으로 한다. 결과를 본 뒤 추가한 매칭은 사후 보조 지표로만 표시한다.
- 에이전트 가설은 모두 inferred다. 가설의 진입점으로 보낸 공격이 성공한 PoC만 confirmed로 올린다. 에이전트의 비취약 판정은 confirmed가 될 수 없으며 coverage 기록으로만 남긴다. 판정 기록에 모델 ID, 프롬프트 ID·SHA-256, 룰 버전을 고정한다.
- 합성 룰 승격 gate는 세 조건을 모두 요구한다: confirmed 사례 탐지, 수정본 비발화, 기준 구성 대비 정밀도·수정본 오경보·정답 밖 결과의 비회귀.
- opengrep taint 룰에서 Flask 요청 source(`--taint-intrafile`)와 헬퍼 매개변수 source(intrafile 없이)를 별도 룰로 나눈다. 한 룰에 두면 헬퍼 반환값 전체가 오염돼 gate에서 걸렸다.

## 대안

- 공개 벤치마크만으로 평가: 오염 가능성 때문에 에이전트 평가에 쓰지 않는다. 엔진 기준선 참고용으로만 후속 실행한다.
- 정답 세트를 저장소에 커밋: 공개되면 이후 평가가 오염된다. 비공개 원격 저장소 생성은 BOSS 결정 사항이라 이번에는 로컬 저장소만 만들었다.
- `feat/opengrep-cwe` 이어받기: 대상 언어가 다르고 ADR 번호가 main과 충돌한다. 절차와 엔진 선택만 재사용했다.
- CodeQL: 독립 엔진이지만 비공개 상용 코드에 대한 라이선스 조건이 확인되지 않아 제외했다.

## 영향·한계

결과는 [실험 문서](../sast-python-engine-loop.md)에 있다. holdout에서 엔진 합집합은 9/15이고 CWE-22·918은 0/3이다. 에이전트 confirmed는 15/15이며, dev confirmed로 합성한 룰은 holdout 탐지를 늘리지 못했다. 에이전트와 정답 작성자가 같은 모델 계열이라 에이전트 수치는 신뢰 판단 근거로 아직 부족하다. 정답 세트는 로컬에만 있어 디스크 손실에 취약하다. 비공개 원격이나 다른 보존 위치는 BOSS 결정이 필요하다. Joern v1 모델은 gate에서 불합격해 편입하지 않았다. CI 실행, DT·릴리스 연결, 에이전트 트리아지 단계는 구현하지 않았다.
