# 라이선스 적용 범위 표현 교정

Node와 이전 이미지에서 소스 고지에 등장하는 모든 조건을 부모 컴포넌트의 `AND` 식으로 합치던 처리를 교정한다. `AND` 자체가 잘못된 연산자인 것은 아니다. 적용 대상과 배포물 포함 여부를 확인하지 않은 상태에서 하나의 바이너리 조건으로 결론 내린 것이 문제다.

## 표현과 검토 단위

표준 `licenses` 필드는 해당 프로젝트 또는 배포 선언의 범위를 표시한다. 이 값만으로 번들 전체의 조건이나 준수 완료를 판단할 수 없다. `hoplites:license-scope:standard-field-scope`가 그 범위를 설명한다.

개별 고지는 대상, 관계, 선언된 조건, 포함 여부, 적용 판단, 원문과 빌드 증거, 검토 작업을 독립적으로 보존한다. 포함 여부와 적용 판단은 confirmed/inferred/unknown으로 구분한다. 의무 이행은 별도이며 현재 전부 not-verified다. 검토 작업은 법적 의무의 자동 판정이 아니다. 같은 라이선스 이름이어도 저작권자와 대상이 다르면 별도 기록으로 유지한다. `OR` 선택과 `WITH` 예외 검토도 대상별로 남긴다.

* Node: 본체 MIT와 타사 고지를 분리한다. 실제 ELF 의존성, 정의된 심볼, 설치된 config.gypi를 함께 확인한다. 이 이미지의 OpenSSL/zlib/libuv는 바이너리 포함이 확인되고, V8은 빌드 설정 근거의 추론이다. 나머지 고지는 포함 및 적용 여부를 모른다고 표시한다. 원문 LicenseRef와 바이트 범위를 보존한다.
* Debian/Ubuntu: DEP5 `Files`별 선언을 바이너리 패키지 전체의 AND로 바꾸지 않는다. 스캐너 선언은 검증되지 않은 선언으로 유지하고, 소스 선택자·저작권자·원문 해시를 별도 후보 범위로 보존한다.
* Java: 기본 GPL/Classpath 배포 조건과 모듈 문서·assembly exception을 분리한다. jrt-fs의 조건은 배포에서 추론한 것이라고 명시한다.
* Erlang/OTP: Apache 프로젝트 조건과 확인된 소스·네이티브 고지를 분리한다. 미해결 상태 표시를 라이선스 식에 넣지 않는다.
* Python: 배포 조건과 설치된 소스·확장 모듈의 조건을 분리한다. 소스 동일성과 빌드 연계 증거를 구분한다. pip RECORD는 최신 main의 처리대로 pip에 연결된 설치 증거로 보존한다.

## 전달과 검증

`license-scopes.json`은 전체 검토 기록, `license-scopes.html`은 사람이 읽는 표다. 두 파일과 원문·단계별 증거가 제출 번들에 포함된다. DT는 긴 속성을 1,024자로 잘라 저장하므로 JSON 기록을 570바이트 조각으로 나누고 base64로 인코딩해 800자 미만의 속성으로 보존한다. DT의 값 양끝 공백 제거도 회피한다. 수집기는 조각 번호의 연속성, 소유자와 기록 ID를 확인해 복원한다. 업로드 검증은 이름·버전·PURL·SHA-256·표준 라이선스와 모든 범위 속성의 값까지 확인한다.

이번 재처리는 기존 고정 이미지의 원본 SBOM과 rootfs를 사용한다. 이전 결과는 덮어쓰지 않는다. `artifacts/license-scope-fixed-*-001/replay-verification.json`에 입력 해시와 관리 단위 비교를 남긴다. Node 236, Java 139, Elixir 28, Ubuntu 93개는 동일하다. Python 125→124는 기존 pip RECORD 관리 항목이 설치 증거로 이동한 것으로 실제 소프트웨어 제거가 아니다.

## 남은 판단

원문의 canonical SPDX 매핑, 일부 고지의 실제 포함/적용, 수신자에게 전달할 고지·소스 제공·변경 표시와 이행 여부는 미완료다. DT 표준 라이선스 칼럼은 여전히 단일 요약이므로 상세 판단에는 범위 보고서를 함께 봐야 한다. 이번 변경은 이러한 미확인 사항을 삭제하거나 준수 완료로 표시하지 않는다. DT API 저장 검증과 사람이 보는 UI 표시 검증은 별개다.

## 스캐너 해시의 라이선스 오표기 교정

일부 스캐너 결과의 `license.name`에는 `sha256:…` 같은 고지 식별용 해시가 들어 있다. 해시는 라이선스 조건이 아니므로 표준 라이선스 필드에서 제외한다. 원본 SBOM은 보존하고, 이전 선언과 변경 필드·처리 규칙을 단계별 증거 및 별도 적용 범위 기록에 남긴다. 유효한 라이선스 선언이 함께 있으면 유지한다. 해시만 있던 경우는 라이선스 미확인으로 남기며 source-wide AND 식이나 추측한 SPDX 값으로 채우지 않는다.

`license_fields.py`는 해시 형태의 이름·ID·전체 식을 검사한다. `public-domain-sha1` 같은 실제 선언 이름과 `LicenseRef-*`는 해시로 오인하지 않는다. 이 검사는 최종 정규화에 적용되며 업로드 전에도 잘못된 값을 거부한다. DT 검증은 라이선스 없는 항목에 이전 값이 잔류하지 않았는지 검사한다. 이것은 형식 오류 검사이며, 나머지 선언의 라이선스 정확도나 완전성을 보증하지 않는다.

`license-scope-fixed-*-002` 결과에서 Node 14, Java 19, Python 14, Ubuntu 11개 항목을 교정했다. Elixir에는 해당 오류가 없었다. 이전 `001` 결과 대비 620개 관리 컴포넌트의 이름·버전·PURL은 모두 유지한다. 별도 적용 범위와 원문 검토 작업도 유지한다.
